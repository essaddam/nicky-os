# Cast générique — plan d’implémentation

> Exécution dans cette console : superpowers:executing-plans, sans nouvel agent.

**But :** observer et piloter les récepteurs Cast explicitement validés.
**Architecture :** adaptateur moli-cast sur moli-androidtv, passerelle API partagée.
**Technologies :** Rust/Tokio, protobuf Cast, DNS borné, Svelte 5.
**Spécification :** [conception](../specs/2026-10-21-cast-design.md).

## Contraintes globales

Activation explicite, aucune publication avant validation ; FIFO 4 ; échéance
absolue du hub ; découverte privée trois secondes/256 paquets/64 candidats ;
JSON API 1 Kio ; coffre et pins ; contrats Philips/Android inchangés. Tests natifs
Rust 1.99.1/-j2, ciblés et Clippy workspace avant revue, complet à la fusion.

## Relecture prioritaire

- Candidat retiré ou remplacé pendant validation : ancienne génération refusée.
- Deux alias du même appareil, ou propriété TV/MA déclarée : aucune double publication.
- Révocation ou reconnexion avant premier poll : aucune ancienne commande ne part.
- Réponse perdue après émission : résultat incertain et journal conservé, aucun rejeu.
- Adresse/source mDNS mensongère : aucun contact tiers, aucun candidat activable.

## Tâche 1 — Configuration et découverte

Fichiers moli-cast/src/{config,discovery,discovery_tests}.rs.
Interfaces Config::check, Candidate, parse_packet, discover. Écrire les contrats
privé/sous-réseau, records DNS/ID/port, compression, limites et construction sans
réseau ; constater le rouge, implémenter, obtenir le vert.
- [x] Contrats rouges puis verts et fixtures synthétiques.

## Tâche 2 — Contrôles récepteur suivis

Fichiers moli-androidtv/src/cast{,_tracked,_receiver_tests}.rs.
Interface additive ReceiverOrder/ReceiverVolume et tracked_receiver_stream ; les
Order/Event et fonctions legacy restent compatibles. Contrats volume/sourdine,
requestId/source/namespace, abandon/délai et refus, puis implémentation minimale.
- [x] Rouge, vert, régressions Cast/Philips/Android.

## Tâche 3 — Activation, coffre et pilote

Fichiers moli-cast/src/{gateway,ownership,driver,transport,model}.rs et tests.
Gateway state/discover/approve/revoke, NativeDriver hors réseau, transport injectable.
Contrats zéro réseau/publication avant validation, génération, propriété unique,
persistance avant pin/ordres, FIFO, perte/reconnexion, abandon après émission.
- [x] Contrats rouge/vert du vrai hub et de la passerelle.

## Tâche 4 — Surfaces et catalogue

API moli-api/src/cast.rs, options/gateways/fabriques moli-os, carte Système,
locales fr/en, integrations/cast et documentation OpenAPI/onboarding. Contrats HTTP
sans PIN/démo/invité, corps invalide/surdimensionné, sélection périmée, révocation.
- [x] Tests HTTP rouges puis verts ; UI validation explicite sans publication implicite.
- [x] Fmt, Clippy workspace, tests ciblés, web/build/i18n et fuites.
- [ ] Commit fixe et soumission Database ; aucun complet avant son tour de fusion.

## Résultats de validation

- Découverte : rouge 2 PASS/3 FAIL, puis cinq contrats verts.
- Volume récepteur : rouge 41 PASS/3 FAIL dans la bibliothèque, puis vert.
- Activation/propriété : rouge 6 PASS/4 FAIL, puis vert ; pilote vrai hub :
  rouge 10 PASS/4 FAIL, puis vert. Pin TLS : rouge 14 PASS/2 FAIL, puis vert.
- Routes HTTP : rouge 1 PASS/2 FAIL, puis trois contrats verts.
- Fabrique : rouge sur le kind absent, puis configuration/construction/gateways
  et réservation préalable du TV au vert.
- Passage final : 255 tests Rust ciblés, zéro échec, aucun exclu (45 bibliothèque,
  31 Android TV, 123 API dont 43 HTTP, 21 Cast, 30 binaire, 5 Philips).
  Deux jobs Cargo et deux threads de tests ; les invitations HTTP avaient
  dépassé leur délai sous la concurrence par défaut, sans modification de leur
  délai ni du client HTTP partagé. Les 43 passent avec cette borne.
- Fmt et Clippy workspace/all-targets/-D warnings ; 56 tests web, build,
  3 506 clés fr/en et contrôle de fuites générique verts. Les avertissements
  Svelte préexistants hors Cast restent visibles au build.
- Parcours navigateur sur données fictives : découverte sans publication,
  consentement, PIN simulé, ancienne génération refusée, validation de la
  nouvelle sélection, pause via hub et désactivation ; captures ordinateur et
  mobile 390 px sans débordement. Aucun appareil réel contacté.
- Contrôle complet réservé au tour de fusion après approbation Database.
