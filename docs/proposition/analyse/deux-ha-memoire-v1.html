3. Les actions : compter les contrats sans inventer les liaisons

Une entrée du catalogue de services devient ici une définition d’action partagée. light.turn_on n’est pas dupliquée pour chaque lumière : ses paramètres et sélecteurs appartiennent au contrat. Le catalogue seul ne dit pas combien d’actions concrètes chaque appareil accepte ; les supported_features, modes, cibles et schémas partiellement expurgés exigent une résolution complémentaire. Aucun service n’a été exécuté pour vérifier une capacité.

4. Coût des lignes : deux représentations clairement séparées

Vue principale : V = un état par entité active, E = tous les équipements du registre, A = toutes les définitions de services, y compris les contrats illisibles réservés. N=V+E+A. Un service est partagé à l’intérieur d’une installation ; les contrats des deux installations ne sont pas dédupliqués entre eux.

Vue développée : on ajoute une fiche par nœud d’attribut JSON, y compris les objets/listes et leurs feuilles. Le record racine des attributs de chaque entité est compté. Cette représentation conserve toute la structure ; elle majore un modèle où les métadonnées seraient stockées uniquement dans des descripteurs partagés. Chaque feuille et conteneur n’est compté qu’une fois.

6. Ce qui manque pour dimensionner exactement les actions par équipement

  • Résoudre chaque service vers les cibles et supported_features réels, sans exécution ; conserver une liste explicite des correspondances non prouvées.
  • Choisir : un contrat partagé + liens compacts par cible, ou une fiche de 64/96 o par action concrète. La seconde représentation peut coûter bien davantage que le nombre de services.
  • Pour K liaisons supplémentaires : ajouter 4K o pour des références u32 seules (index et portée en plus), ou 64K / 96K o si chaque liaison devient une fiche autonome. K n’est pas inventé ici.
  • Ajouter les entités désactivées si elles doivent être préchargées, les types autorisés mais non observés, les maxima des champs texte et les quotas de composites.
  • Comparer sous Linux les allocations de la représentation complète, le RSS anonyme, les lectures et mutations à ×1/×10. Le banc de layout déjà exécuté prouve 64/96 o, pas le coût complet de ces exports.
