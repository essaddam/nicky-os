Une copie conforme,sans journal sur disque.

Ta question : comment tenir chez les secours, local et distant, une copie exacte de la maison sans écrire de journal sur le disque ? Réponse : un rang pour tout ce qui est critique, une file en mémoire, l'état complet par MQTT, et un pont fait maison, à deux bouts, qui gère les tampons. La durabilité vient des autres machines. Trois classes de données, les workflows par MQTT, les modes et leurs passages, le redémarrage par les pairs ; chiffré par un banc : deux vrais courtiers rumqttd, un lien qui coupe et bat, un vrai pont Mosquitto pour comparer.

Ce que la proposition établitUne copie exacte, sans aucun journal sur disque : la durabilité vient des autres machines, et le pont est à nous.
01 / LA COPIE

Sans journal sur disque

Un rang s, une file en mémoire, l'état complet par MQTT : aucune perte, mémoire identique, exécutions comprises.

Mesuré
02 / LE PONT

Fait maison, à deux bouts

Le courtier transporte, le pont comble. Celui de rumqttd perd 3 011 messages sur 8 000 ; Mosquitto, 960 sans prévenir.

Mesuré
03 / L'ABSENCE

Recopier l'état, pas rejouer

Une journée d'absence : 1,8 s à 1 Mbit/s pour 101 Ko, contre 69 s et 7,7 Mo en v1.

Mesuré
04 / LES CLASSES

Critique, historique, hors MQTT

Le critique exact à tout instant ; l'historique au mieux, complété plus tard ; la vidéo et les gros fichiers par leur propre chemin.

Proposé
05 / LES WORKFLOWS

Par MQTT, dans le même rang

Leur état (wf/) voyage avec les valeurs ; leur journal d'exécution (run/, puis hist/) avec l'historique.

Proposé
06 / LE DISQUE

L'instantané seulement

48 fsync et 5,7 Mo par jour, contre jusqu'à 165 000 fsync pour la v1, et 236 Mo pour state.json aujourd'hui.

Calculé
07 / LE PRIX

Une panne de tout, sans onduleur

Sans journal, elle perd jusqu'à la période de l'instantané. Avec un onduleur, ou un distant à jour : rien.

À choisir
08 / LE REDÉMARRAGE

Le plus avancé l'emporte

La mémoire d'un pair d'abord, l'instantané ensuite ; jamais actif avec moins qu'un pair (le piège de Redis).

Proposé
09 / LES MODES

Six modes, une porte

Reprise, rattrapage, à jour, isolé, actif, arrêt figé ; l'époque est la seule porte vers l'actif.

Proposé
10 / LES INTÉGRATIONS

Une seule instance active

Jeton qui tourne, comptes qui bannissent, identifiants MQTT fixes, effets en double : le secours est prêt, jamais branché.

Inventaire
11 / LE DISTANT

NetBird, le même pont

Copie, alerte et cloud. Sur un lien qui tombe toutes les 15 s, 0 perte, mémoire identique.

Mesuré
12 / AUJOURD'HUI

Aucun mode passif

Toute instance lancée agit ; le coffre est lu une fois ; l'arrêt ne range pas les exécutions. Première marche, utile même sans secours.

Écart
